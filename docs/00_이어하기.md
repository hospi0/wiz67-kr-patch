## 다음 할 일 (우선순위)
1. **메뉴 동적 칸 훅 (VII 먼저)** — ★설계 1차 = docs/01 끝 절(분류 패치 + 그리기 입구 훅 + KANJI12 남는 칸에 메뉴 글꼴·코드) — 확인된 경로: 문자열 그리기 `0x06033CB0` → 분류 `0x0603392C`(한자 = 6 미지원) → 그리기 `0x06033B1C`(R6 = 코드+0x7D61) → 프레임 표 `0x06071166`(FONT_1 = 프레임 0‥370, VRAM 0x25C10000+80×n).
   - ⏳ `0x06033B1C` 안 종류별 프레임 번호 계산(キャラクターをつくる = 96 151 157 98 114 83 81 35 14 73 로 검산).
   - ⏳ 훅 코드 둘 빈 공간 · 한 프레임 안에서 칸 재사용해도 이미 그린 글자가 안 바뀌는지(VDP1 은 프레임 끝에 그림 — 최대 위험) · KANJI12 RAM 주소를 가리키는 변수.
   - 설계: 한글 코드 → 새 종류 → 가나 칸 ~170개 LRU → KANJI12 글자 10줄을 4bpp 80 B 로 VRAM 에 쓰고 그 프레임으로.
   - 그다음 VI(WIZ6.BIN·SL.BIN)에서 같은 루틴 주소 찾기(바이트 패턴으로).

## 번역 TSV 추출 (2026-10-02, 훅 설계 전) — `python tools/extract.py` → `my files/tsv/` 32개(각 29KB 이하)
- 열 = ID · 위치 · 구분 · 공유 · 원문 · 번역. ID 접두어 6-(VI 대사)·7-(VII 대사)·X-(실행 파일)·N-(나레이션). 같은 원문은 한 줄(공유 = 개수, 빌더가 같은 원문 전부에 넣을 것).
- VI 대사 3,628줄(4.3만 자)·VII 대사 6,987줄(11.1만 자): 허프만 조각 단위, 제어 바이트 {01}‥{1F}, `@`·공백 원문 그대로. ⛔영어만 된 조각(HUMAN·아이템 영문명 — 일본판도 영어)은 안 뽑음.
- 실행 파일 2,067줄(1.4만 자): WIZ6·WIZARDRY·SL 합쳐 중복 제거, 구분 «실행N» = 원래 바이트(제자리 한도), 위치 = 파일@오프셋. 잡음 거름 = 4 B 정렬(또는 앞 NUL)·첫 글자 전각·대사 말뭉치 한자·반각 섞이면 가나 2자 이상. 아이템·몬스터·주문 이름(가타카나)은 여기.
- 나레이션 91줄(4,255자): CDSOP0‥3·BCFOP·CPKPLAY·CDS_END0‥3 의 [SJIS·FF02(줄)·FExx(화면 넘김)]…FC 블록, 한 줄 = 한 화면, 위치 = 파일@블록#화면.
- 자투리(VI 대사 끝·VII 대사 끝·실행 끝) = `wiz_자투리.tsv`.
